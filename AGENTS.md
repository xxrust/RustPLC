# Agent Notes

- When introducing a new `TransitionAction` variant, update all dependent layers together: semantic lowering (`src/semantic/mod.rs`), runtime bridging (`src/runtime_bridge.rs`), ST codegen (`src/codegen/st.rs`), and safety/diagnostic matchers (`src/verification/safety.rs`).
- Extern-function support spans AST + IR: keep `topology.extern_functions`/call bindings aligned across `src/ast/mod.rs`, `src/ir/mod.rs`, and semantic topology/state-machine lowering tests.
- Extern `action: call` return bindings are type-checked against `[topology] variable` declarations in semantic analysis; declare bound variables up front and keep extern signature tests line-aware.
- Extern declaration contract checks (duplicate names, non-empty `rust_module`, positive `time_bound_us`, and Phase-1 scalar signature types) should stay in semantic signature collection so declaration errors surface before call-site validation.
- Runtime extern contract enforcement belongs in `src/extern_functions.rs` (`ExternFunctionRegistry`): keep arg-count/range/timeout/runtime errors centralized there, and use `with_time_source` in tests for deterministic timeout assertions.
- Runtime extern execution now flows through `runtime_core::Action::CallExtern`: `Runtime::tick*` without a handler returns `ExternCallRequiresHandler`, so extern-enabled flows must call `tick_with_extern`/`tick_with_trace_and_logs_and_extern` and adapt registry `Vec` results into the provided output slice.
- Runtime extern contract violations (range/timeout/runtime) surface from `tick_with_extern` as `RuntimeTickError::ExternCallFailed`; integration tests should assert both the outer function context and the nested `ExternRuntimeError` details.
- For DSL-level extern fallback/retry flows, use `Runtime::tick_with_extern_error_code` with a declared `[topology] variable last_error: int` slot and map `ExternRuntimeError` via `extern_runtime_error_code`; this captures call failures into variable-driven branching without adding new DSL keywords.
- Scheduler-level extern guardrails are split by stage: non-pure cross-branch concurrency checks live in semantic task validation (`src/semantic/mod.rs`), while tick-budget (`tick_ms` vs summed `time_bound_us`) enforcement lives in runtime bridging (`src/runtime_bridge.rs`).
- `ExternFunctionRegistry::new` bootstraps built-in externs (`add`/`multiply`/`quadratic_fit` plus stateful `pid_update`); tests built with `with_time_source` start empty and must call `register_builtin_math_functions()` / `register_builtin_control_functions()` explicitly, and can use `reset_builtin_pid_state()` for deterministic PID assertions.
- Causality extern modeling spans semantic + verification: allow causality chain nodes to reference devices, `[topology] variable`s, and extern function names in `build_constraint_set`, then in `src/verification/causality.rs` add call-site edges `arg_vars -> function` and only treat `pure: true` externs as deterministic transforms via `function -> binding` edges.
