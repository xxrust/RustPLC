## 🎯 项目定位

RustPLC 是工业控制领域的**形式化验证编译器**，目标是通过数学证明替代人工审查和现场调试，让 AI Agent 能够安全地生成工控程序。

### 核心价值主张

```
传统 PLC 开发: 手写梯形图 → 人工审查 → 现场调试 → 发现碰撞/死锁
RustPLC 方案:  AI 生成 DSL → 编译期证明 → 直接部署（零运行时错误）
```

## 🔬 技术亮点

### 1. 形式化验证深度

- **BMC 深度**: k=4~8，覆盖典型状态空间
- **Z3 集成**: SMT 求解器自动证明
- **反例生成**: 失败时给出最短路径
- **k-归纳**: 证明任意深度安全性

### 2. 编译器工程质量

- **错误恢复**: Parser 支持部分解析
- **增量编译**: IR 缓存可复用（待启用）
- **并行验证**: 四引擎真并行，充分利用多核
- **诊断分级**: Error/Warning/Info 三级

### 3. 运行时确定性

- **无动态分配**: 所有内存编译期分配
- **固定精度**: 避免浮点非确定性
- **单线程执行**: 无并发竞态
- **WCET 可计算**: 每个周期执行时间有上界

### 4. AI-Friendly 设计

- **声明式 DSL**: 适合 LLM 生成
- **约束自动注入**: 减少人工编写
- **结构化错误**: 便于 AI Agent 解析
- **修复建议**: 直接可执行的改进方案

## 🎓 核心创新

### 1. 四引擎并行验证架构

业界首创在编译期同时证明四类属性，不依赖运行时检查。

### 2. 设备语义库系统

将设备约束从 DSL 中分离，支持设备定义复用和自动约束注入。

### 3. 分层项目组织模型

从拓扑到工艺模型再到 PLC 任务的三层语义分离，清晰度远超传统 PLC 项目。

### 4. 状态证明门禁

强制要求所有物理状态必须由传感器、操作者输入或显式例外证明，杜绝隐式假设。
