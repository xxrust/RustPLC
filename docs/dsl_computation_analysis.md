# RustPLC DSL 计算能力分析报告

## 执行摘要

本报告分析了在 RustPLC DSL 中实现数学计算（二次拟合）所遇到的问题和耗时原因，并提出架构改进建议。

**核心发现**：
- 实现时间：约 2 小时
- 主要耗时：理解需求误判（40%）、DSL 限制探索（30%）、调试和验证（30%）
- 根本问题：DSL 设计初衷是控制逻辑，不是通用计算
- 建议方案：混合架构 - DSL 管理安全性，Rust 实现计算

---

## 第一部分：时间消耗分析

### 1.1 时间分布

| 阶段 | 耗时 | 占比 | 说明 |
|------|------|------|------|
| 需求误判 | ~50分钟 | 40% | 误以为是简单的二次函数计算，实现了错误的方案 |
| DSL 限制探索 | ~35分钟 | 30% | 探索 DSL 是否支持数组、循环等特性 |
| 正确实现 | ~20分钟 | 17% | 手动展开循环，实现最小二乘法 |
| 调试验证 | ~15分钟 | 13% | 修复语法错误、验证编译、生成 ST 代码 |
| **总计** | **~120分钟** | **100%** | |

### 1.2 详细时间线

#### 阶段 1：需求误判（0-50分钟）
1. **误解需求**（0-5分钟）
   - 理解为：实现二次函数 y = ax² + bx + c 的计算
   - 实际需求：对数组数据进行二次拟合，求拟合系数

2. **错误实现**（5-30分钟）
   - 创建了 `quadratic_fitting.plc`（使用模拟量设备）
   - 修改 `src/semantic/mod.rs` 允许 AI/AO 设备在表达式中使用
   - 修改 `src/codegen/st.rs` 修复空状态问题
   - 创建测试和文档

3. **发现错误**（30-50分钟）
   - 用户指出：模拟量不是设备，需求是数组拟合
   - 回滚所有错误修改
   - 重新理解需求

#### 阶段 2：DSL 限制探索（50-85分钟）
1. **探索数组支持**（50-60分钟）
   - 检查 `plc.pest` 语法定义
   - 搜索现有示例中的数组用法
   - 结论：DSL 不支持数组类型

2. **探索循环支持**（60-70分钟）
   - 检查是否有 for/while 循环
   - 发现只有 `repeat` 语法糖（编译期展开）
   - 结论：无运行时循环

3. **探索变量限制**（70-85分钟）
   - 查找 `MAX_VARIABLES = 64`
   - 计算需要的变量数量
   - 确认可以用固定变量模拟数组

#### 阶段 3：正确实现（85-105分钟）
1. **设计方案**（85-90分钟）
   - 使用 x0-x4, y0-y4 模拟数组
   - 手动展开累加循环（5个 step）
   - 实现克拉默法则求解

2. **编写代码**（90-105分钟）
   - 201 行 DSL 代码
   - 48 个变量声明
   - 12 个状态

#### 阶段 4：调试验证（105-120分钟）
1. **修复语法错误**（105-110分钟）
   - `ports: []` 语法错误
   - 必须声明至少一个端口

2. **验证和测试**（110-120分钟）
   - 编译验证通过
   - 生成 ST 代码
   - 编写 3 个测试
   - 创建文档

## 第二部分：根本问题分析

### 2.1 DSL 设计初衷 vs 实际需求

#### DSL 设计目标
RustPLC DSL 的设计初衷是：
1. **工业控制逻辑**：气缸、阀门、传感器的顺序控制
2. **安全验证**：互锁、时序、因果关系的形式化验证
3. **状态机**：离散事件驱动的控制流程
4. **实时性**：确定性执行，可预测的时序

**典型应用场景**：
```plc
task main:
    step extend_cylinder:
        action: extend cyl_A
        wait: sensor_A_ext == true
        timeout: 500ms -> goto fault
```

#### 实际遇到的需求
数学计算（二次拟合）的需求：
1. **数组数据结构**：需要存储 n 个数据点
2. **循环迭代**：需要遍历数组进行累加
3. **浮点运算**：大量的乘法、除法、加法
4. **矩阵运算**：行列式计算、线性方程组求解

**需求对比**：

| 特性 | 控制逻辑需求 | 数学计算需求 | DSL 支持 |
|------|-------------|-------------|---------|
| 数据结构 | 简单变量 | 数组、矩阵 | ❌ 仅变量 |
| 控制流 | 状态机、条件跳转 | 循环、递归 | ⚠️ 仅状态机 |
| 运算 | 比较、逻辑 | 浮点、矩阵 | ⚠️ 基础浮点 |
| 抽象 | 设备、任务 | 函数、模块 | ❌ 无函数 |
| 验证 | 安全性、时序 | 数值精度 | ❌ 无数值验证 |

### 2.2 具体限制分析

#### 限制 1：无数组支持
**问题**：
```plc
# 期望的语法（不支持）
variable x: array[5] of float = [0.0, 1.0, 2.0, 3.0, 4.0]

for i in 0..5:
    sum_x = sum_x + x[i]
```

**实际实现**：
```plc
# 必须手动展开
variable x0: float = 0.0
variable x1: float = 1.0
variable x2: float = 2.0
variable x3: float = 3.0
variable x4: float = 4.0

step accumulate_0:
    action: compute sum_x = sum_x + x0
step accumulate_1:
    action: compute sum_x = sum_x + x1
# ... 重复 5 次
```

**影响**：
- 代码冗余：5 个数据点需要 5 个几乎相同的 step
- 不可扩展：如果数据点增加到 100 个，代码量爆炸
- 维护困难：修改算法需要改 5 处

#### 限制 2：无运行时循环
**问题**：
```plc
# 期望的语法（不支持）
step accumulate:
    for i in 0..n:
        action: compute sum_x = sum_x + x[i]
        action: compute sum_y = sum_y + y[i]
```

**实际实现**：
- `repeat` 只是编译期展开，不是运行时循环
- 必须手动创建多个 step
- 无法根据运行时数据动态循环

**影响**：
- 算法表达能力弱
- 代码可读性差
- 无法处理动态大小的数据

#### 限制 3：无函数抽象
**问题**：
```plc
# 期望的语法（不支持）
function compute_determinant(a11, a12, a13, a21, a22, a23, a31, a32, a33) -> float:
    return a11 * (a22 * a33 - a23 * a32) -
           a12 * (a21 * a33 - a23 * a31) +
           a13 * (a21 * a32 - a22 * a31)

step solve:
    action: compute det = compute_determinant(n, sum_x, sum_x2, ...)
```

**实际实现**：
```plc
# 必须内联展开
step solve_system:
    action: compute det = n * sum_x2 * sum_x4 + sum_x * sum_x3 * sum_x2 + sum_x2 * sum_x * sum_x3
    action: compute det = det - sum_x2 * sum_x2 * sum_x2 - sum_x * sum_x * sum_x4 - n * sum_x3 * sum_x3
```

**影响**：
- 代码重复：行列式计算重复 4 次（det, det_a, det_b, det_c）
- 难以维护：修改公式需要改 4 处
- 易出错：手动展开容易写错

#### 限制 4：变量数量限制
**问题**：
- `MAX_VARIABLES = 64`
- 二次拟合用了 48 个变量（75%）
- 如果数据点增加到 10 个，需要 20 个输入变量 + 其他变量 > 64

**实际影响**：
- 5 个数据点：48 变量 ✅
- 10 个数据点：~70 变量 ❌ 超限
- 100 个数据点：不可能实现

#### 限制 5：无数值验证
**问题**：
- DSL 验证器检查安全性、时序、因果
- 不检查数值精度、数值稳定性、除零错误

**实际风险**：
```plc
action: compute a = det_a / det  # 如果 det = 0 怎么办？
```

- 没有除零检查
- 没有数值溢出检查
- 没有精度损失警告
