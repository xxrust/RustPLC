- What was implemented
  - Added new component-fault contract module: `src/component_faults.rs`.
  - Introduced explicit per-component fault kind enum:
    - `jammed`, `motion_timeout`
    - `stuck_on`, `stuck_off`, `chatter`
    - `lost_step`, `stall`, `direction_reversed`
  - Added unified fault event container:
    - `ComponentFaultEvent { at_ms, duration_ms, target_component_id, fault_kind, params }`
  - Added parser/validator entrypoints:
    - `parse_component_fault_events_json`
    - `parse_component_fault_events_value`
  - Added stable validation issue contract:
    - `ComponentFaultIssue { code, path, message }`
    - `ComponentFaultValidationError`
  - Implemented parameter validation rules:
    - `motion_timeout` requires `params.timeout_ms >= 1`
    - `chatter` requires `period_ms >= 1` and `duty_percent` in `1..=99`
    - `lost_step` requires `ratio` in `(0.0, 1.0]`
  - Exported module in crate root: `src/lib.rs`.
- Quality checks

  - `cargo check --workspace`

  - `prd.json`
  - `progress.txt`
- **Learnings for future iterations:**
  - Patterns discovered (e.g., "this codebase uses X for Y")
    - A single fault-event envelope with typed `fault_kind` plus kind-specific `params` checks keeps schema compact while preserving strong validation.
  - Gotchas encountered (e.g., "do not forget to update Z when changing W")
    - Keep strict numeric range checks in validators; downstream simulation logic should not need to re-validate malformed fault params.
