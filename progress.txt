# Ralph Progress Log
Started: 2026-03-09 00:00:00 CST

## Codebase Patterns
- `axis.move_relative/absolute` 参数解析走四层：`src/parser/plc.pest` → `src/parser/mod.rs` → `src/ast/mod.rs` → `src/semantic/mod.rs`，改动必须同步。
- 轴动作参数的语义优先级固定为 `inline overrides > action params 引用 > device.motion_param_set`，并在语义阶段写回最终值再降级到 IR。
- 轴故障语义需跨层同构：`src/ir/mod.rs` 与 `crates/runtime-core/src/lib.rs` 的 `AxisFaultKind/AxisFaultCategory` 必须同名同语义，并通过语义降级统一填充 `category/vendor_code`。
- `pest` 规则存在 `boolean_value` 与 `identifier` 二选一时，必须把 `boolean_value` 放在前面，否则 `true/false` 会被吞成标识符并触发类型误报。
- `parallel` 合成状态命名约定固定：`__parallel_<n>_fork` → `__parallel_<n>_branch_<m>_active` → `__parallel_<n>_branch_<m>_done` → `__parallel_<n>_join`，回归测试与验证逻辑依赖该模式。
- `runtime_core::Program` 结构字段变更需同步四处：`src/runtime_bridge.rs`（桥接填充）、`src/main.rs`（内置 `SIM_PROGRAM`）、`crates/codegen/src/lib.rs`（生成器模板）、`crates/board-rp2040/build.rs`（默认固件程序模板）。
- 轴故障停机可观测性采用双日志阶段：先 `axis_stop_transition_enter` 再 `axis_stop_transition_completed`，并用 `axis_stop_transition_log_message_id(stop_mode, phase)` 做稳定断言，避免硬编码 message_id。
- `axis.move_*` 异常分流使用“主桶 + 细分 routes”模式：主桶分支永远必填且作为回退，细分 `kind/code` 路由按声明顺序首条命中。
- `axis.move_*` 细分 fault route 的匹配语义在 IR 由 `resolve_axis_fault_route_target` 固化；当前 runtime 轴回调故障会直接返回 `RuntimeError::AxisFault`，路由匹配回归更适合在状态机/IR 层做快照。
- runtime-core 在一个 tick 内会连续执行非阻塞状态（`Action/Goto/已满足 wait`）；写回归时若要精确逐 tick 断言，需在步骤间加入 `delay` 或未满足 `wait` 做节流。
- `axis.move_*` 参数值语法中的 `number` 不接受带符号前缀；负值会在 parser 阶段先报错，语义层的非正数校验应使用 `0` 场景覆盖。
- 垂直轴制动顺序检查应仅对“出现 `set <axis>.enable off` 且轴设备具备 `model_ref/config_ref`”的目标轴生效，避免把 legacy 无 profile 轴用例误判为配置错误。
- `axis_fault_contract` 的传播目标在语义阶段统一收敛：`followers` 走 `cam_coupling master->slave`（可传递），`group` 走 `tags.functional_group` 交集，且始终包含故障轴自身。
- `axis.move_*` 参数白名单建议使用 `pest` 兜底规则（如 `axis_move_unknown_arg`）并放在已知字段分支后，再在 parser 输出稳定错误码（`[AXIS-013]`），避免回退到不稳定的 `expected ...` 文案。
- `must_complete_within_worst_case` 的 timeout 预算不能只看 `StepStatement::Timeout`；`axis.move_*` 的内联 `timeout` 也必须在时序估算里显式计入。
- 轴异常因果链校验需覆盖 `timeout` 与 `on_reject/on_motion_fault/on_safety_fault` 全分支；只校验 fault 桶会漏掉 timeout 恢复链断裂。
- `trace-doctor` 诊断码演进采用“双码并存”模式：`issue_code` 使用新主码（如 `AXF-*`），同时保留 `legacy_issue_code`（`DIAG-*`）以保证向后可解析；新增诊断字段优先做可选增量（如 `source_location`）。
- DSL 合约变更后要同步更新 `.codex/skills/plc-gen/SKILL.md` 与 `.codex/skills/plc-system/SKILL.md`，确保生成流程不会输出已被编译器白名单拒绝的字段。
