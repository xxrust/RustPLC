## Codebase Patterns
- 在 liveness 夹具中若使用 `axis.move_*`，必须补齐 `timeout/on_reject/on_motion_fault/on_safety_fault`，否则会在语义门禁阶段失败并无法进入 liveness 检查。
- 并发 task 与阻塞 step 的术语、推进规则与自动阻塞范围，以 `docs/architecture/signal-direction.md` 为单一语义源。
- 本仓库最终回归门禁优先使用完整 `cargo test`，仅 `cargo test --lib` 不能替代端到端回归。
- Task 级 pending action 元数据应从 step 语句收集，不应只依赖 transition.actions；阻塞语句可能让 transition 丢失 action。
- `runtime-core` 在 `no_std` 约束下使用定长数组（`MAX_ACTIVE_TASKS`）和活跃计数管理 task context，避免动态分配。
- `runtime-core` 每个 tick 必须按 task 声明顺序（索引升序）遍历全部 active task；单 task 命中 blocking step 只阻塞自身，不阻塞同 tick 其他 task。
- runtime step 离开判定应集中在统一 completion 决策函数（action/delay/wait 共用），避免分支内重复写跳转条件。
- 当 action step 出现 Pending 长时动作时，后续 tick 必须从挂起动作继续轮询，不能重放挂起动作之前的即时 action（避免重复 side effect）。
- `axis.move_relative/axis.move_absolute` 默认是 blocking 长时动作；即使 DSL 未显式写 `wait`，也要用 Pending 轮询驱动 step 留驻，并覆盖 Pending->Done 与 Pending->Fault 集成回归。
- axis `timeout/on_*fault` 语义若在 IR 中以 action 内分支存在，必须由 `runtime_bridge` 预先解析成 runtime `StepId` 元数据；`runtime-core` 在 Pending 轮询阶段消费这些元数据完成分流。
- `runtime_bridge` 生成并发 runtime task 时，优先选择“无跨 task 入边”的 root task 作为 active 集合；若不存在 root task，回退到 IR 初始 task 以避免旧工作流被并发全激活破坏。
- `verification::safety` 并发全局状态建模要复用 runtime root task 选择口径，并在 `ConcreteState` 中显式携带 task 级当前位置与 pending 标记，避免验证和执行对 active task 集合的理解漂移。
- 若预算测试通过 `on_complete: goto <self>` 构造循环来触发 same-tick budget 告警，需同时声明 `allow_indefinite_wait: true`（或提供 timeout），否则会先被 liveness SCC 门禁拦截。
- timing 并发验证要同时给出 task 局部耗时与 active tasks 的全局 `max` 完成时间，并保留顺序 `sum` 作为对照；`must_complete_within_worst_case` 需显式纳入 pending 动作和 timeout 上界。
