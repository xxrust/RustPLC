## Codebase Patterns
- Run `cargo check --workspace` for typecheck and `cargo test --workspace` for regression gate before committing.
- Keep DSL syntax decisions in dedicated docs under `docs/` and link story completion back to `prd.json` + `progress.txt`.
- For new `[topology]` DSL entries, keep grammar (`src/parser/plc.pest`), parser wiring (`src/parser/mod.rs`), and semantic topology cloning (`src/semantic/mod.rs`) in sync.
- When adding a new `action:` DSL command, keep `action_command` grammar alternatives, `parse_action_statement` match arms, and parser unit tests synchronized.
- Introducing a new IR `TransitionAction` variant requires coordinated updates in semantic lowering, runtime bridge conversion, ST codegen rendering/inference, and verification matchers to keep compile/runtime behavior consistent.
- Extern call semantics rely on predeclared `[topology] variable` symbols for return bindings; signature checks should validate arg/binding arity+types and report step-level line numbers.
- Keep extern declaration contract validation in semantic signature collection (`collect_extern_function_signatures`) so declaration-level diagnostics fire before per-step call-site checks.
- Keep extern runtime contract checks centralized in `src/extern_functions.rs`; use `ExternFunctionRegistry::with_time_source` in tests so timeout assertions stay deterministic.
- `Action::CallExtern` executes only through runtime extern-aware APIs (`tick_with_extern` / `tick_with_trace_and_logs_and_extern`); plain `tick*` methods intentionally return `ExternCallRequiresHandler`.
- For DSL retry/fallback/error handling, map extern failures into a declared `[topology] variable last_error: int` via `Runtime::tick_with_extern_error_code` + `extern_runtime_error_code`, then branch in tasks using normal `wait`/`timeout` transitions.
- Integration tests for extern contract guardrails should assert `RuntimeTickError::ExternCallFailed` plus nested `ExternRuntimeError` payload details (function context and offending index/value).
- `ExternFunctionRegistry::new()` bootstraps built-ins (`add`, `multiply`, `quadratic_fit`, `pid_update`); deterministic tests built with `with_time_source` must register needed built-ins explicitly and use `reset_builtin_pid_state()` before PID assertions that require a fresh integrator.
- Extern scheduler guardrails are stage-split: detect non-pure cross-branch conflicts during semantic task validation, and enforce per-tick `time_bound_us` budget against configured `tick_ms` in runtime bridging.
- Runtime ticks may consume multiple immediate action-only transitions in a single `tick_with_extern` call; add wait/delay boundaries when tests need one control update per scheduler tick.
- Causality extern chains are modeled across semantic + verifier: allow causality nodes to reference devices/variables/extern names, wire call-site `arg -> function` edges, and only propagate `function -> binding` for `pure: true` externs.
- Performance regression gates should bundle four artifacts together: benchmark emitter (stable JSON schema), thresholds JSON, baseline JSON, and a script-level contract test that can inject fixture payloads via CLI.
- Extern developer tooling should keep one source of truth: register via `register_extern_function!`, derive `signatures()`, and parser-roundtrip `generate_dsl_declaration_stubs()` output to prevent runtime/DSL signature drift.
