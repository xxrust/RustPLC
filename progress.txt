## Codebase Patterns
- Run `cargo check --workspace` for typecheck and `cargo test --workspace` for regression gate before committing.
- Keep DSL syntax decisions in dedicated docs under `docs/` and link story completion back to `prd.json` + `progress.txt`.
- For new `[topology]` DSL entries, keep grammar (`src/parser/plc.pest`), parser wiring (`src/parser/mod.rs`), and semantic topology cloning (`src/semantic/mod.rs`) in sync.
- When adding a new `action:` DSL command, keep `action_command` grammar alternatives, `parse_action_statement` match arms, and parser unit tests synchronized.
- Introducing a new IR `TransitionAction` variant requires coordinated updates in semantic lowering, runtime bridge conversion, ST codegen rendering/inference, and verification matchers to keep compile/runtime behavior consistent.
- Extern call semantics rely on predeclared `[topology] variable` symbols for return bindings; signature checks should validate arg/binding arity+types and report step-level line numbers.
- Keep extern declaration contract validation in semantic signature collection (`collect_extern_function_signatures`) so declaration-level diagnostics fire before per-step call-site checks.
- Keep extern runtime contract checks centralized in `src/extern_functions.rs`; use `ExternFunctionRegistry::with_time_source` in tests so timeout assertions stay deterministic.
- `Action::CallExtern` executes only through runtime extern-aware APIs (`tick_with_extern` / `tick_with_trace_and_logs_and_extern`); plain `tick*` methods intentionally return `ExternCallRequiresHandler`.
- `ExternFunctionRegistry::new()` bootstraps built-in math externs (`add`, `multiply`, `quadratic_fit`); deterministic tests built with `with_time_source` must call `register_builtin_math_functions()` explicitly.
