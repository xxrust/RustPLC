## Codebase Patterns
- Scope for this Ralph run is WPM-v1 Phase 1-3 only. Do not include classify, rework, recirculation, or continuous geometry.
- Workpiece semantics must close through semantic checks, verification, runtime bridge, runtime-core execution, and example regressions.
- ST backend is explicitly out of scope for this Ralph run.
- `crates/runtime-core` is `no_std`, so workpiece token and lineage storage must stay bounded and allocation-free.
- Keep workpiece lineage as an append-only edge store separate from token records; consumed tokens stay in the token store and are traced through lineage by token id.
- Reuse `tests/workpiece_model_phase23.rs`, `tests/examples_integration.rs`, and `examples/workpiece_*.plc` wherever possible.
- Unsupported workpiece behavior must fail explicitly. Do not silently drop semantics in bridge, runtime, or verification.
- `crates/runtime-core/src/lib.rs` keeps most runtime-core fixtures inline; when `Program`, `AxisMotionCommand`, or pending-axis state gains fields, update those in-file test literals together before trusting the crate test baseline.
- When `runtime_core::Action` or `Program` changes, also update exhaustive action matches and static `Program` fixtures in `src/main.rs`, `src/sim_regress.rs`, `crates/codegen/src/lib.rs`, and `crates/sim/*`; those crates compile against runtime-core directly and fail fast on stale variants/fields.
- Runtime ingress seeding must be driven by actions that actually consume a source endpoint (`acquire` / `transfer` from that endpoint), not by blindly preloading every declared `ingress_site`; otherwise mount-only carrier flows start with falsely occupied slots.
- Phase 2 carrier flows need token metadata that distinguishes “free-standing at slot X” from “mounted on slot X”; `current_location` alone is not enough once `mount` / `transform carrier` / `unmount` are executable.
- Phase 1 workpiece effects require a unique active token at the source endpoint. Treat `0` as underflow, `>1` as duplicate occupancy ambiguity, and destination-capacity violations as explicit overflow errors.
- When semantic already blocks a malformed workpiece contract but verification still needs its own regression, build the normal `ConstraintSet`/`StateMachine` first and then mutate the lowered structures in the test to isolate verification responsibility.
- Carrier-slot bridge lowering must expand `carrier.slot[*]` / grid selectors into concrete runtime ingress-egress endpoints and synthesized carrier `workpiece_sites`; otherwise runtime seeding and slot-addressed actions drift apart even when IR is correct.
- Phase 2 safety verification must mirror runtime token semantics: track `mounted_slot` separately, let `mount` reuse a same-type free-standing token already at the slot, treat `acquire/transfer/finish` as free-standing-only, and keep mounted association intact across `transform carrier`.
- Phase 3 `split` is still type-level in IR. Runtime must consume exactly one active token of `source_type` globally and let child tokens inherit the source token's `current_location` and `mounted_slot`; if future stories need endpoint-level routing, add that data to IR instead of guessing in bridge/runtime.
- Phase 3 `merge` is also still type-level in IR. `inputs` are only DSL refs, so `runtime_bridge` must resolve the concrete input-type multiset from the target `merge(...)` derivation and lower both refs and types into `runtime-core`; runtime should then reject duplicate consumed refs or arity drift explicitly instead of guessing hidden instance metadata.
- Phase 3 verification fixtures now need real source seeding too: abstract split/merge-only programs with no ingress-backed instance should fail exact safety on the first `split`/`merge`, so tests that need later-phase assertions should use runtime-style ingress (`plate.slot[*]`, `acquire/transfer`, etc.) or mutate lowered constraints/state machines after build.
- Canonical workpiece regression coverage should read `examples/workpiece_*.plc` directly for compile, bridge, and verification checks; keep inline PLC fixtures only when the example intentionally lacks prerequisites for runtime execution, such as source seeding or terminal cleanup.
