# Ralph Progress Log
## Codebase Patterns
- 当 DSL 关键字弃用时，先在 `parse_plc` 入口做逐行预检查并返回带行列号的迁移错误，再交给 pest 做常规语法解析。
- DSL 新增结构化属性时，按 `plc.pest` 规则 + `parser/mod.rs` 的 `expect_*` 解析辅助函数成对落地，避免语义层直接解析字符串。
- 语义拓扑构图应以 `TopologySection.connections` 为主输入，并通过 relation 回溯到设备声明行号，保证 `driven_by/reports_to/detects` 的错误都可定位。
- `component_topology` 新增规则校验时，优先复用端口校验阶段解析出的有效连接上下文，再叠加规则检查，避免重复 endpoint 解析造成报错口径漂移。
- 废弃 DSL 字段后，需同步更新 verifier/runtime/scenario 相关测试夹具与诊断文案，否则 `parse_plc` 的迁移拦截会导致回归测试批量失败。
- 为废弃字段加 CI 防回流时，优先用 `git diff` 扫描新增行而非全仓 grep，这样不会被历史文档/负例夹具阻塞。
- 新增 DSL 结构化字段时，优先保持 AST/API/store 的固定 shape（一致字段名 + 空值默认结构），前端解析入口做 normalize，避免 UI 侧散落空值判断。
- `topology` 相关 API（`get/save/parse-plc`）若承载新元数据，建议统一走“服务端归一化后再返回/落盘”的模式，避免前端与文件工件出现字段漂移。
- 前端涉及拓扑导出/保存/写回时，统一复用 `web-ui/src/utils/topologySerialization.ts` 的 `toComponentTopology`，避免 edges 的 `signal/relation/from_port/to_port` 序列化口径不一致。
- 画布级可视化状态（过滤/分组高亮/区域定位）应放在 store，`TopologyCanvas` 仅基于 state 派生 `renderNodes/renderEdges`（`hidden + style`），避免污染持久化拓扑数据。
- `parse-plc` API 契约回归建议直接在 `crates/web-server/src/main.rs` 调用 `parse_plc_topology(Json(ParsePlcTopologyRequest))` 断言 JSON 字段，避免起服务端到端测试成本。
- 前端端口契约应在 `topologyStore.normalizeTopologyNode` 中统一通过 `resolveNodePorts` 归一化，并在导出时去除 `portContractFallback` 推导字段，避免把降级推断反写进持久化拓扑。
- CLI 场景链路回归优先采用 `scenario-init` 生成夹具后立刻执行 `scenario-validate`（同一临时目录），避免依赖手写 YAML 随 DSL 进化失效。
- 文档契约测试若绑定 `docs/*.md` 路径，优先支持“主路径 + 归档路径”候选读取（如 `docs/已实现/`），并移除已废弃文档对应测试，避免文档迁移导致 CI 假阳性失败。
- 新增拓扑语义 diff 能力时，先复用 `parse_component_topology_json` 做两侧归一化，再比较 `nodes/ports/relations/tags`，可保证 diff 与 validate 语义一致并直接落盘为审计工件。
