# Ralph Progress Log
## Codebase Patterns
- When the repo root is both `[package]` and `[workspace]`, use `cargo test --workspace` to run member-crate tests (plain `cargo test` only targets the default package).
- For `#![no_std]` crates that still want unit tests/doctests, add `#[cfg(test)] extern crate std;`.
- In `src/parser/plc.pest`, when an alternation allows both `measured_value` (e.g. `50bar`) and `number`, list `measured_value` first so `50bar` doesn't partially match as `50`.
- In `src/parser/plc.pest`, when `number` and `integer` are both allowed, list `number` before `integer` to avoid `2.0` being partially consumed as `2`.
- In `runtime-core`, `delay`/`timeout` are evaluated as `elapsed = now_tick - step_entered_tick`, and they fire when `elapsed >= configured_ticks` (so `after_ticks: 0` is immediate on the entry tick).
- In `crates/sim::SimIo`, input changes scheduled for tick `N` are applied when `advance_tick()` moves to `N`, so they are visible during the runtime's tick-`N` evaluation (tick-0 changes are applied in `SimIo::new`).
- For `crates/sim` plant-style dynamics, keep the plant as a deterministic tick-step that *returns* input updates, and call it from `SimIo::advance_tick()` (after applying scenario inputs) to avoid borrow-checker pitfalls with `&mut self` callbacks.
- Waveform exports are deterministic by construction: VCD assigns idcodes in a fixed order (`di<N>` then `do<N>`) and uses timestamps `tick * tick_ms` with `$timescale 1ms`.
- For human-friendly YAML parse errors, use `serde_path_to_error` so errors include a field path (e.g., `inputs[0].set.digital_inputs`).
- `serde_yaml` enum representations can be surprising (it expects YAML tags like `!Variant`); for author-friendly scenario files prefer struct-shaped keys like `faults: - sensor_stuck: { at_ms, target, value }`.
- To unit-test verifier behavior that semantic validation would normally reject (e.g., "skipped rule binding"), build constraints normally and then mutate `ConstraintSet` inside the test.
- `src/runtime_bridge.rs` builds `runtime-core::Program<'static>` by leaking boxed slices/strings (`Box::leak`) to keep the runtime API simple for now; treat this as OK for CLI/tests but avoid in long-lived processes.
- The repo is not currently rustfmt-clean; treat `cargo fmt --check` as non-gating unless you are intentionally doing a formatting pass.
- CLI integration tests in this repo should invoke the compiled binary via `env!("CARGO_BIN_EXE_rust_plc")` and verify artifacts on disk.
- The main `<file.plc>` CLI now writes a structured verification report to `out/<stem>.verification_report.json` by default; in tests prefer `--report <temp-file>` to avoid shared output collisions.
- Batch SIL regress runs live in `rust_plc::sim_regress`: it scans `.plc`/scenario YAMLs recursively, writes per-case `trace.jsonl`/`report.json` under `out/sim-regress/case_XXXX`, and emits a summary JSON.
- No-board trace regression gate is available as `rust_plc no-board-gate`: it runs SIL + `virtual-board` + `trace-diff` and writes `sil_trace.jsonl`, `board.log`, `board_trace.jsonl`, `diff_report.json` under `--out-dir`.
- For embedded workspace crates, keep a host-stub `main()` behind `cfg(not(target_os = "none"))` so `cargo test --workspace` stays green while firmware code is `cfg(target_os = "none")`.
- Release-style artifacts should include a `manifest.json` that hashes the exact on-disk files (plus `size_bytes`) so integration tests can verify integrity deterministically.
