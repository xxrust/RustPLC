# Ralph Progress Log
## Codebase Patterns
- 当 DSL 关键字弃用时，先在 `parse_plc` 入口做逐行预检查并返回带行列号的迁移错误，再交给 pest 做常规语法解析。
- DSL 新增结构化属性时，按 `plc.pest` 规则 + `parser/mod.rs` 的 `expect_*` 解析辅助函数成对落地，避免语义层直接解析字符串。
- 语义拓扑构图应以 `TopologySection.connections` 为主输入，并通过 relation 回溯到设备声明行号，保证 `driven_by/reports_to/detects` 的错误都可定位。
- 废弃 DSL 字段后，需同步更新 verifier/runtime/scenario 相关测试夹具与诊断文案，否则 `parse_plc` 的迁移拦截会导致回归测试批量失败。
- 为废弃字段加 CI 防回流时，优先用 `git diff` 扫描新增行而非全仓 grep，这样不会被历史文档/负例夹具阻塞。
- 新增 DSL 结构化字段时，优先保持 AST/API/store 的固定 shape（一致字段名 + 空值默认结构），前端解析入口做 normalize，避免 UI 侧散落空值判断。
