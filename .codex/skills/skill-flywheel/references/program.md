# 研究程序

## 目的

`skill-flywheel` 不是 backlog 执行器，而是研究编排器。

每一轮 cycle 都应先有一份简短但明确的研究程序，再去跑盲测和归因。不要先跑一轮，再事后补一个理由。

## 一轮程序至少写清什么

## 写法原则

1. 研究问题要窄。一次只验证一个主要假设。
2. 成功信号必须可观察，不要写成抽象口号。
3. 决策规则要面向下一步动作，而不是面向解释本身。
4. 程序是稳定协议，不是复盘日志。复盘写进 `logs/`，不要反过来把日志混进程序。
5. 如果准备并行跑多个实例，必须先写清“哪些输入固定，哪些因素允许变化”，否则并行只会制造噪声。

## 推荐长度

- `program.md` 最好控制在 20 到 60 行内
- 一轮只保留 1 个主研究问题
- 如果主问题变了，就开下一轮，而不是在同一份程序里不断追加
